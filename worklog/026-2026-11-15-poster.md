# 026 — Poster: one 16:9 slide built by a script from the result files
**Date:** 2026-11-15   **Tag:** poster, code, decision   **ROADMAP:** 9.2   **Status:** built; user review open

## What
Built the poster as `poster/poster.pptx` and `poster/poster.pdf`: one 16:9 slide
(13.33 × 7.5 in) with the problem, the limits of the existing frameworks, contributions, data
and protocol, the method (diagram, gate rule, compact Algorithm 1), the test results (three
headline numbers, Table 1, Figure 2), findings, limitations, conclusion and five references.
It is produced by `python scripts/build_poster.py --pdf`.

## Why
ROADMAP 9.2; the poster replaces the 10-slide presentation (format change of 12 Nov). Plan:
`.claude/plans/poster.md`. User decisions of 15 Nov:
- The sample poster is only a sample: the design is free, and everything about the project
  should be on it.
- PPTX + PDF, shown on screen, so the sample's 16:9 size is kept.
- No logos.
- Tool: asked whether to use PPTX, Canva or Figma. PPTX from a `python-pptx` script was chosen:
  the numbers must come from `docs/results/*.csv` (as in the report), the build must be a
  README command, and the slide can be rendered and checked here with LibreOffice. Canva's
  connector generates designs from prompts and cannot place exact tables; Figma has no
  connector; a LaTeX poster gives no editable PPTX.

## How
- `trafficrl.eval.poster`: loads the result CSVs, turns the report's number macros
  (`latex.number_macros`) into plain text, fills `{metric@model@condition}` placeholders,
  builds Table 1 (five agents + three ablations) and Figure 2 (travel time under detector
  noise, worst-case regret, gate firing rate).
- `poster/content.yaml`: all poster prose, impersonal voice, numbers as placeholders.
- `scripts/build_poster.py`: places text boxes, a native table, Figure 1 as native shapes
  and Figure 2 as a 300 dpi PNG; `--pdf` converts with LibreOffice.
- Checked by rendering the PDF to PNG and looking at it after each build (6 builds).

Problems met and what was done:
- **Too much text for the slide.** The first build overflowed in all three columns. Text was
  cut, the "Type" column of the table dropped, and the hypotheses moved into Findings.
- **The report's architecture diagram is unreadable at 4 in wide** (about 4 pt text). Replaced
  by a reduced diagram in native shapes.
- **Drop shadows** appeared on the shapes although `shadow.inherit = False` was set: LibreOffice
  follows the theme effect reference in `p:style`. The script removes that element.
- **YAML key `yes`** was parsed as the boolean `True`; renamed to `fallback`.
- **No Calibri / Cambria-compatible font** is installed, so the render check would not be
  reliable for those fonts. The poster uses Arial (Liberation Sans has the same widths).
- `python-pptx` and `pptxgenjs` were both missing; `python-pptx` was installed.

## Result
- `poster/poster.pdf`: 1 page, 960 × 540 pt. Visual check of the last render: no clipped or
  overlapping text, nothing outside the slide.
- Numbers on the poster equal the result files: UG-MARL 295.4 ± 1.1 s, DQN 292.2 ± 0.6 s,
  IDQN 307.9 ± 1.4 s, Max-Pressure 320.8 s on the clean test flow; 420.5 s at noise 0.2;
  worst-case regret 6.8 s against 62.2–414.6 s for the baselines.
- `pytest`: 296 passed, 1 skipped (6 new tests in `tests/eval/test_poster.py`).
  `ruff check src tests scripts`: clean.
- Not verified: the look in Microsoft PowerPoint (only LibreOffice was available).
- Smallest text: 6.2 pt (references, diagram details), body 7.5–7.8 pt. This is meant for
  full-screen viewing, not for print.
- No simulation, no `--final`, no experiment-log row.
