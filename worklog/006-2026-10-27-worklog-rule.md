# 006 — Work log rule
**Date:** 2026-10-27   **Tag:** setup   **ROADMAP:** —   **Status:** done

## What
Created `worklog/`. Every meaningful piece of work gets its own numbered file that records
what was done, why, how and the result. An index sits in `worklog/README.md`.

## Why
The user wants a permanent record of the project's history. It also feeds:
- the report (methodology and limitations),
- the slides,
- the viva, where we must explain *why* each choice was made,
- the progress reviews.

Alternatives considered:
- **One `WORKLOG.md` file.** Rejected by the user in favour of separate files per piece of
  work, numbered in order.
- **Subfolders by category.** Rejected: they break the single timeline. A tag field shows
  the category instead.

## How
- **Format:** `worklog/NNN-YYYY-MM-DD-slug.md` with the sections What / Why / How / Result /
  Files & commits / Next. The full rules and template are in `worklog/README.md`.
- **Back-filled** entries 001–005 from the conversation and the git history.
- **Wired into the workflow:**
  - `CLAUDE.md` holds the rule.
  - `prime` reads the latest entries at the start of a session.
  - `execute` and `commit` include a step to write an entry.
  - The ROADMAP Decision Log links each decision to its entry.
- Claude writes the entry at the end of each task without asking. The user can edit any
  entry.
