# 017 — Phase 6: proposed UG-MARL (attention, Q-ensemble, uncertainty gate)
**Date:** 2026-11-11 – 2026-11-12   **Tag:** decision, code, experiment   **ROADMAP:** 6.1–6.7   **Status:** done

## What
Designed (11 Nov, with the user) and built (12 Nov, native Ubuntu) the proposed agent,
UG-MARL. It combines neighbour attention, a bootstrapped K-head Q-ensemble and an uncertainty
gate that falls back to Max-Pressure. The work covers the core changes it needs, explanation
logging, the three ablations, the K × d grid study, 5-seed finals of the full model and two
trained ablations, gate calibration on clean + perturbed validation, a σ validity check, the
Phase 6 validation table and learning curves, and the mathematical write-up
(`docs/methodology.md`). Plan: `.claude/plans/phase6-ugmarl.md` (all 14 steps ticked,
deviations listed there).

## Why
ROADMAP Phase 6 (F4, F7, F10; R4, R5; G8). The plan fixes every methodological choice before
any UG-MARL training, as the guidelines require, and is written so that another session on
native Ubuntu can execute it (section "Handoff").

Decisions (user, 11 Nov; full table and rejected alternatives in the plan, summary in the
ROADMAP Decision Log):

| Topic | Chosen | Rejected, and why |
|---|---|---|
| Weights | one network shared by all intersections | per-intersection nets (cannot run on Hangzhou, 12× parameters); id embedding (not transferable) |
| Ensemble | shared encoder + K independent MLP heads | K full networks (K× compute); K linear heads (correlated, small σ) |
| Attention | one GAT layer, one attention head | multi-head (blurred explanations); two layers (whole-graph replay) |
| σ | std over heads of Q at the greedy action | vote disagreement (only K + 1 levels) |
| τ | p-th percentile of σ on clean val; p chosen on clean + perturbed val; one p, τ per seed-model | clean val only (would select "never fire"); fixed p (arbitrary); safety-constrained (new constant); one global τ (σ scale differs per model) |
| Gate in training | evaluation only | active in training (−gate would need its own runs; gate and weights entangled) |
| Exploration | ε-greedy on mean Q | head sampling (two changes at once vs. the baselines) |
| Head diversity | Bernoulli(0.8) masks + independent init | randomized priors (extra component); init only (σ may collapse) |
| Training search | full grid K {3, 5, 10} × d {32, 64, 128}, seed 0 | wider random search (sparse on K, d); 4-run grid (weak evidence) |
| Ablations | −attention, −ensemble trained on 5 seeds now; −gate from the same checkpoints | smoke runs only / seed 0 only (no ablation numbers before Phase 7) |
| If no gain over DQN | lock the best grid config, no extra tuning | pre-declared second stage (more tuning than the baselines) |
| Math write-up | `docs/methodology.md` | writing directly in `report/` (template not set up) |
| Extra | σ validity check | SHAP, vote logging, animation hook (not selected now) |
| Platform | long runs on native Ubuntu if 0.1b is done, else WSL dev | — |

## Result
Validation, Jinan `real_2000`, seeds 0–4, native Ubuntu (`docs/results/val_phase6.md`):

| Model | Avg travel time (s) | Max wait (s) | Fallback | Params |
|---|---|---|---|---|
| Fixed-Time | 434.8 (det.) | 1124 | — | 0 |
| Max-Pressure | 326.1 (det.) | 1334 | — | 0 |
| DQN | 299.8 ± 1.0 [298.5, 301.1] | 637 | — | 23 304 |
| IDQN | 312.7 ± 2.5 [309.7, 315.8] | 717 | — | 279 648 |
| **UG-MARL** (K 3, d 128, p* 80) | 302.3 ± 1.1 [300.9, 303.6] | 761 | 0.211 | 157 720 |
| −gate | 301.8 ± 0.8 [300.8, 302.8] | 691 | 0 | 157 720 |
| −attention | 301.9 ± 1.3 [300.3, 303.6] | 655 | 0.212 | 59 032 |
| −ensemble | 303.7 ± 1.7 [301.5, 305.8] | 713 | 0 | 89 864 |

Reading (validation only; test decides in Phase 7, and validation also selected K, d, p and
the checkpoints, so these scores are optimistic):
- **H1 pattern holds on val:** UG-MARL beats IDQN and Max-Pressure, and the CIs do not
  overlap. It does **not** beat DQN, which H1 does not require: 302.3 vs 299.8 s.
- **H3 pattern not supported:** −attention is as good as the full model (301.9 vs 302.3 s)
  with 37 % of the parameters. On a 3 × 4 grid with this reward, neighbour information gives
  no measurable gain on validation.
- **Ensemble:** −ensemble (K = 1) is 1.4 s worse than the full model, with overlapping CIs.
- **H2 is mixed on val.** On clean validation the gate costs 0.5 s and raises max wait
  (761 vs 691 s, CIs overlap); it fires on 21 % of decisions (≈ 1 − p*/100 ✓). With noisy
  detectors (gate calibration table) the ungated policy collapses: 599 s at noise 0.1 and
  909 s at noise 0.2. The gated policy holds 376 / 423 s, and max wait at noise 0.2 drops
  from 3307 to 1238 s. With 10–20 % detector dropout the gate makes no difference.
  Minimum acceptable outcome (max wait no worse than Max-Pressure, 1334 s): met on clean
  val (761 s) and at noise 0.2 (1238 s).
- **σ validity:** σ is a strong detector of corrupted inputs (median ×4.2 at noise 0.1,
  ×10.8 at noise 0.2). It barely moves under dropout (×1.02–1.06) and does **not** rank
  value errors on clean states (Spearman ρ(σ, |TD|) = 0.03 ± 0.03). So the gate acts as an
  out-of-distribution switch, not as a predictor of in-distribution mistakes. This goes in
  the report's limitations.
- Gate check: τ = 0 reproduces Max-Pressure exactly (326.1141 s), and τ = ∞ equals −gate.
- Decision latency (idle machine): UG-MARL 1.25 ms per decision batch, −attention 0.79 ms.
  The baselines' latencies come from 11 Nov runs, so compare them only roughly.
- Failures / dead ends:
  - The first σ figure had overlapping tick labels. Fixing it repeated 5 TD episodes, so
    the `sigma_check_ugmarl_final_s*` rows appear twice in the log with identical values.
  - Decision latency was first measured under training load (9.9 ms). Those evaluations
    were re-run on an idle machine, and the table reads the later runs.
  - The 2-episode smoke model gave a misleadingly low fallback rate. It was gridlocked, and
    the trained models match the expected rate.
  - The first worklog-update script failed on a section anchor; nothing was written, so it
    was re-run.

## Contributions (running list for the report / poster; user rule: 4–5 innovations)
1. **Uncertainty gate with a provably-stable fallback.** A learned per-intersection policy
   hands decisions to Max-Pressure when its ensemble disagrees. If the gate always fires, the
   controller *is* Max-Pressure (stability under Varaiya's assumptions). Measured result:
   under noise 0.2 it holds travel time at 423 s where the ungated policy reaches 909 s.
2. **Validation-calibrated τ under perturbed inputs.** τ is a per-model percentile of σ,
   and one p is chosen on clean + noisy / dropout validation, because clean data alone would
   select "never fire". All pre-registered and validation-only.
3. **Bootstrapped Q-ensemble on a shared, transferable network** (K heads, one encoder, one
   parameter set for all intersections → zero-shot to Hangzhou in 7.4).
4. **Neighbour attention with masked slots** for variable neighbourhoods; per-decision
   attention weights are logged. On val it is not better than no attention (honest
   negative so far).
5. **σ validity evidence and per-decision explanation logs.** σ tracks input corruption
   but not clean value error, and every decision is logged with σ, τ, fallback, learned vs
   Max-Pressure phase and attention.
