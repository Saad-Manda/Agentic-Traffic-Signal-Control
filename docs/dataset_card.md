## 1. Overview

| | Jinan | Hangzhou |
|---|---|---|
| **Role** | primary: train / val / test | held-out generalisation city (final evaluation only) |
| **Network** | 3 × 4 grid, 12 signalised intersections | 4 × 4 grid, 16 signalised intersections |
| **Flow files** | 3 (one per split) | 3 (all held-out) |
| **Episode** | 3600 s (1 h) per flow file | 3600 s per flow file |
| **Area (per CoLight paper)** | Dongfeng sub-district, Jinan, China | Gudang sub-district, Hangzhou, China |
| **Origin** | real roadside-camera vehicle observations, converted to CityFlow flows by the CoLight authors | same |

**Unit of observation:** one vehicle trip: entry time plus the ordered list of roads it
travels. The dataset defines the RL *environment*. The agent's training data (transitions)
is generated by interacting with the simulator on the training flow file only.

Virtual intersections are network boundary nodes where vehicles enter and leave. They
have no signal and are not agents.

**Split type.** Jinan uses *whole flow files*: three separate one-hour demand scenarios on
the same road network, so no vehicle record is shared or resampled between splits.
Hangzhou is a *group-wise (location) split*: no Hangzhou data is used for training,
tuning, normalisation or EDA plots. Rationale and rules: `.claude/reference/database.md`.

## 4. Data dictionary

### 4.1 Flow file (`anon_*.json`): JSON list, one object per vehicle

| Field | Type | Unit | Meaning / values in this data |
|---|---|---|---|
| `startTime` | int | s | time the vehicle is inserted at the first road of its route (0–3599) |
| `endTime` | int | s | end of the generation window. Here always `= startTime`, so each record is exactly one vehicle |
| `interval` | float | s | generation interval inside the window. Always 1.0 (irrelevant when start = end) |
| `route` | list[str] | road IDs | ordered roads travelled. First road starts at a boundary node; the last road ends at a boundary node in 98–99 % of records (the rest end inside the network). Length 2–19 |
| `vehicle.length` | float | m | 5.0 (all vehicles) |
| `vehicle.width` | float | m | 2.0 |
| `vehicle.maxPosAcc` | float | m/s² | 2.0, maximum acceleration |
| `vehicle.maxNegAcc` | float | m/s² | 4.5, maximum deceleration |
| `vehicle.usualPosAcc` | float | m/s² | 2.0 |
| `vehicle.usualNegAcc` | float | m/s² | 4.5 |
| `vehicle.minGap` | float | m | 2.5, minimum gap to the vehicle ahead |
| `vehicle.maxSpeed` | float | m/s | 11.111 |
| `vehicle.headwayTime` | float | s | 2, desired time headway |

All vehicles share one profile, so the data has a single vehicle class: no buses, trucks
or pedestrians. There is no vehicle ID field. CityFlow assigns `flow_<i>_<j>` IDs per file.

### 4.2 Road network (`roadnet_*.json`)

| Object / field | Type | Unit | Meaning |
|---|---|---|---|
| `intersections[].id` | str | — | `intersection_<col>_<row>` |
| `intersections[].point` | {x, y} | m | position |
| `intersections[].virtual` | bool | — | true = boundary node (no signal, not an agent) |
| `intersections[].roads` | list[str] | — | incident road IDs |
| `intersections[].roadLinks[]` | object | — | allowed movement: `type` (`go_straight` / `turn_left` / `turn_right`), `startRoad`, `endRoad`, `laneLinks` (lane-to-lane paths). 12 per signalised intersection |
| `intersections[].trafficLight.lightphases[]` | {time, availableRoadLinks} | s, indices | 9 phases: **phase 0** = 5 s transition (right turns only). **Phases 1–8** = the 8 standard green phases (through / left pairs), each also allowing the 4 right turns |
| `roads[].id` | str | — | `road_<col>_<row>_<dir>` (dir 0 = E, 1 = N, 2 = W, 3 = S) |
| `roads[].startIntersection`, `endIntersection` | str | — | direction of travel |
| `roads[].points` | list[{x, y}] | m | polyline. Length = distance between end points |
| `roads[].lanes[]` | {width, maxSpeed} | m, m/s | 3 lanes per road (left / through / right), 4 m wide, 11.111 m/s |

Agent action space (to be fixed in Phase 4): choose one of the 8 green phases (1–8). The
environment inserts phase 0 for the 5 s transition.

## 5. Quality checks (full audit: `docs/data_audit.md`, 10 Nov 2026)

The full audit (`python scripts/audit_data.py`) found **0 defects** in all six flow files and
both road networks. It also documents three properties that are kept as released: 1–2 % of
trips end inside the network instead of at a boundary node, 3–4 % of routes pass an
intersection twice, and the Jinan training flow has a five-minute low-demand period. The
checks below were done at selection and are confirmed by the audit.

- All 6 flow files parse. All routes reference roads that exist in the road network (0 invalid
  references). Every record is a single vehicle. Start times lie inside the 3600 s episode.
- No duplicate records within a file.
- Overlap between files: only 2–5 % of (startTime, route) pairs coincide between any two
  files of a city. That is consistent with chance given ~3600 start seconds and a few hundred
  routes, so the files are independent demand scenarios, not subsamples of each other.
  Shared *routes* are expected: each pair runs on the same road network.
- **Privacy:** no vehicle IDs, plates, timestamps of real dates, or personal data. File
  names are prefixed `anon_`. Records are aggregated, synthetic-ID vehicle trips.

## 6. Known limitations (state in the report)

- **Grid topologies only.** Both cities are regular grids with uniform road lengths, so we
  cannot claim the method generalises to irregular networks (RESCO Cologne / Ingolstadt
  would test that, but they are SUMO-only).
- **One hour per scenario, one vehicle class, homogeneous lanes.** No pedestrians, buses,
  incidents or sensor noise. The simulator gives perfect observations.
- **One flow file per Jinan split.** Each split is one demand scenario, so variation
  across evaluation runs comes from seeds (and simulator randomness), not from many
  different days. CIs are over seeds, which is a statement about training stochasticity,
  not about demand variability.
- **Undocumented provenance details**: collection dates and file-suffix meaning (see §2).
